# 四子游戏隐私数据地图

> 状态：当前权威隐私设计基线
> 产品决策确认日期：2026-08-01
> 官方要求最后核验日期：2026-08-01
> 说明：本文件用于约束代码、SDK、隐私政策和应用商店声明。每次增加 SDK、权限、远程服务或数据字段时必须先更新本文件并重新核验商店声明。

## 1. 已确认的隐私原则

- Phase 1 至 Phase 4 不接入广告和应用内购买。
- 不做行为分析，不使用广告标识，不建立用户画像。
- Sentry 仅用于匿名崩溃和性能诊断，默认开启，用户可以在设置中关闭。
- Sentry 默认去除敏感字段和棋局内容。
- Phase 3 在线身份是本地随机设备 ID，不要求手机号、邮箱或真实姓名。
- 在线统计与设备 ID 关联，不自动跨设备同步。
- 设置页提供“删除在线数据并重置身份”。
- 隐私政策、应用内说明和商店数据声明必须描述最终构建中所有第一方及第三方 SDK 的实际行为。

## 2. 数据流总览

| 数据类别 | 首次出现阶段 | 处理位置 | 是否离开设备 | 主要用途 | 用户控制 |
|---|---:|---|---|---|---|
| 设置与偏好 | Phase 1 | 本地存储 | 否 | 音效、音乐、震动、动效、诊断和主题设置 | 设置页修改；清除应用数据 |
| 当前对局自动存档 | Phase 1 | 本地存储 | 否 | 首页继续未完成对局 | 结局或明确放弃后清除；清除应用数据 |
| 本地统计与最近20局历史 | Phase 1 | 本地存储 | 否 | 统计和回放 | 应用内清除能力；清除应用数据 |
| LAN 连接信息 | Phase 1 | 两台设备间局域网 | 是，仅同一局域网内传输 | 房间发现、连接和权威同步 | 用户主动进入 LAN；退出房间 |
| 匿名崩溃与性能诊断 | Phase 1 | Sentry | 是 | 定位崩溃、ANR/卡顿和性能问题 | 默认开启；设置中关闭 |
| 界面语言 | Phase 2 | 本地或系统设置 | 否 | 中英日界面选择 | 系统或应用设置 |
| 匿名在线设备 ID | Phase 3 | 本地和在线服务器 | 是 | 匹配、重连、战绩归属 | 删除在线数据并重置身份 |
| 在线对局记录与统计 | Phase 3 | 在线服务器数据库 | 是 | 可靠在线对战、对局记录和统计 | 删除在线数据；保留期在 Phase 3 发布前确认 |
| 语音输入和识别结果 | Phase 4 | 设备语音框架或系统/第三方语音服务 | 待所用引擎核验 | 语音落子和冥想交互 | 用户主动启用；麦克风权限；系统设置 |

## 3. Phase 1 本地数据

### 3.1 设置与偏好

可能包含：

- 音效、音乐和震动开关及音量。
- 动效、粒子和减少动态效果设置。
- 诊断开关。
- 主题选择。
- AI 难度。
- 首次启动和教程状态。

约束：

- 只用于本地功能，不发送给行为分析服务。
- 正式 1.0 后字段变化须迁移，不得静默丢失。
- 隐私政策应说明清除应用数据会删除这些本地设置。

### 3.2 自动存档、统计和回放

可能包含：

- 棋盘状态、当前行棋方和落子历史。
- 对局模式、难度、先手、结果、时长和吃子统计。
- 最近 20 局完整回放数据。

约束：

- Phase 1/2 仅保存在设备本地。
- 当前对局在每次确认落子后自动保存，结局或明确放弃后清除。
- 已完成对局最多保留最近 20 局；超出后按产品规则删除最旧记录。
- 这些棋局内容不得进入 Sentry event、breadcrumb、日志附件或性能 span 字段。
- 本地双人、AI、LAN 都可以写入本地统计，但不得因此自动上传。

## 4. Phase 1 LAN 数据

LAN 仅由用户主动进入，数据在同一局域网的两台设备间交换。

必要数据可能包括：

- 房间显示名称、mDNS 服务类型、设备局域网地址和端口。
- Host/Client 角色、执棋颜色、协议版本和状态序号。
- 棋盘快照、当前行棋方、落子列表、被吃棋子列表。
- 回合绝对截止时间、剩余时间、未吃子计数和重连状态。

约束：

- 只发送完成 LAN 对局所需的数据。
- 不引入远程中转服务器或云端保存。
- 房间关闭后停止发现、注销服务并关闭连接。
- LAN 地址、房间名、棋盘快照和走法不得被 Sentry 或普通日志上传。
- Android 和 iOS 权限说明应明确写“局域网对战”，不得写成含糊的在线分析用途。
- 权限拒绝时不得崩溃，也不得阻止单机模式使用。

### Android 本地网络注意事项

Android 官方说明：target SDK 36 或更低时，本地网络访问仍由 `INTERNET` 权限隐式允许；Android 17/SDK 37 起会引入强制的本地网络运行时权限。Phase 1 仍需用 Android 16 的限制测试开关验证 mDNS、TCP 和 UDP 路径，为后续 target SDK 升级预留处理逻辑。

官方来源于 2026-08-01 核验：[Local network permission](https://developer.android.com/privacy-and-security/local-network-permission)。

## 5. Sentry 匿名诊断

### 5.1 允许目的

- 捕获未处理异常和崩溃堆栈。
- 收集应用版本、操作系统版本和性能时序，以定位兼容性和卡顿问题。
- 区分 development、后续 staging 和 production。

### 5.2 禁止发送

- 用户真实姓名、手机号、邮箱或广告标识。
- 精确位置、局域网 IP、公网 IP 的主动记录。
- 房间名、匿名在线设备 ID、socket ID、match ID。
- 棋盘状态、落子历史、被吃棋子、回放数据或语音指令。
- 自由输入文本、网络请求体、WebSocket 消息体或数据库记录。
- 密钥、DSN 管理凭证、Authorization header、Cookie 或环境文件内容。

### 5.3 实现门禁

- 默认关闭 PII 发送能力，例如设置 `sendDefaultPii=false`。
- 在 `beforeSend`、breadcrumb 过滤和日志桥接处执行字段白名单或脱敏。
- 不把游戏状态对象直接附加到 event、context、tag 或 span。
- 诊断开关关闭后停止发送新的 crash/performance event；本地设置应立即生效。
- DSN 可以按环境注入，但符号上传 token 和管理凭证只能保存在 CI secret 中。
- Android 上传 mapping/symbols，iOS 上传 dSYM；上传过程不得包含用户数据。
- 发布前使用故意触发的测试事件核验环境、版本、脱敏和关闭开关。
- Sentry 项目端同时配置数据清洗、最小必要保留期和访问权限。

## 6. Phase 2 iOS 隐私增量

- Phase 2 的数据类别与 Phase 1 相同，只增加界面语言和 iOS 平台诊断信息。
- `NSLocalNetworkUsageDescription` 和 `NSBonjourServices` 仅用于 LAN。
- Phase 2 不包含语音功能，不应提前请求麦克风权限。
- App Store Connect 的 App Privacy 回答必须包含 Sentry 等第三方 SDK 的实际收集行为。
- 隐私政策 URL 是 iOS 应用的发布必填项。

Apple 官方来源于 2026-08-01 核验：[Manage app privacy](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy) 和 [App privacy details](https://developer.apple.com/app-store/app-privacy-details/)。

## 7. Phase 3 在线数据

### 7.1 匿名身份

- 首次使用在线功能时在设备本地随机生成 ID。
- 不要求手机号、邮箱、真实姓名或社交账号。
- 不使用广告 ID 作为身份。
- 不自动跨设备同步；重置身份后新设备 ID 与旧记录不再自动关联。
- 匿名设备 ID 只提交给在线服务端用于匹配、身份绑定、重连、历史和删除，不向对手返回，也不进入普通日志或诊断事件。

### 7.2 服务端数据

为了完成可靠在线功能，服务端可以保存：

- 匿名设备 ID。
- 匹配房间 ID、双方匿名 ID、执棋颜色和协议版本。
- 权威落子历史、结果、超时/断线结算原因和完成时间。
- 与匿名 ID 关联的在线统计和最近对局记录。

不得保存：

- 通讯录、真实姓名、手机号、邮箱、广告 ID 或精确位置。
- 语音录音或语音指令。
- 与可靠在线对战无关的行为轨迹。

### 7.3 删除、保留与安全

- 设置页提供“删除在线数据并重置身份”。
- 删除请求成功后清除该匿名 ID 的在线资料和可关联对局/统计；客户端只有收到服务端删除成功确认后才能生成并持久化新身份，失败时保留旧身份以便重试。如确有安全或法律保留要求，必须在隐私政策中说明范围和期限。
- 数据保留期限、备份保留期限和删除完成时限必须在 Phase 3 发布前由项目方确认。
- staging 和 production 数据库、密钥和 Sentry 环境完全隔离。
- 网络使用 TLS；数据库和备份加密；生产访问遵循最小权限。
- 服务日志和 Sentry 不记录完整棋局、匿名 ID 或消息体。

## 8. Phase 4 语音数据

Phase 4 实施前必须完成一次针对最终语音引擎的专项数据流核验：

- 录音是在设备本地处理，还是发送给操作系统或第三方语音服务。
- 识别音频和文本由谁保存、保留多久、在哪个区域处理。
- 离线和在线识别行为是否不同。
- 用户拒绝麦克风权限时应用如何降级。

发布基线：

- 只有用户主动进入语音功能后才请求麦克风权限。
- 应用不得把录音、识别文本或语音棋局指令发送给 Sentry。
- 是否允许应用自身保存录音或识别文本必须在 Phase 4 发布前明确决定；未明确前不得持久化或上传到自有服务器。
- 普通对局语音和冥想模式的隐私说明必须使用用户能够理解的语言，并与系统权限弹窗保持一致。

当前代码边界：隐藏冥想组合页只在挂载后加载存档/运行时，加载成功后才构造无平台副作用的候选生产 Adapter；页面会先展示中英日用途说明，只有用户点击启用后才调用可替换的权限端口。权限端口只读取或请求 `Permission.microphone`，识别原文仅作为瞬时 sample 进入严格解析，不进入 Adapter 状态字符串、日志、存档、遥测或网络。当前仍未在平台清单中声明麦克风/语音识别权限，也未把该组合页接入 Home 或正式导航。该边界不代表操作系统或第三方语音服务的数据处理方式已经核验。

## 9. 商店声明与隐私政策门禁

### Google Play

- 所有发布应用都要完成准确的 Data Safety 表单，包括第三方 SDK 行为。
- 即使声明不收集数据，也必须提交隐私政策。
- 隐私政策须在 Play Console 和应用内提供，使用公开、可访问、非地域限制、非 PDF 的 URL。
- Phase 1 的 Data Safety 至少要根据最终 Sentry 配置重新判断崩溃日志、性能数据、设备信息和标识符类别，不能直接套用模板。

官方来源于 2026-08-01 核验：

- [Provide information for Google Play's Data safety section](https://support.google.com/googleplay/android-developer/answer/10787469)
- [Google Play Developer Program Policy](https://support.google.com/googleplay/android-developer/answer/17190352)

### App Store

- iOS 应用必须提供隐私政策 URL。
- App Privacy 必须覆盖开发者和第三方 SDK 的数据收集及用途。
- 数据流变化后要及时更新 App Store Connect 回答。

官方来源于 2026-08-01 核验：[Manage app privacy](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy)。

## 10. 发布前待项目方补充

- 开发者展示名称或法律主体。
- 隐私联系和支持邮箱。
- 公开隐私政策 URL；无官网时可单独托管静态隐私页面，不要求建设完整官网。
- Sentry Flutter 和服务端项目、DSN、事件保留期和访问角色。
- Phase 1 发布国家/地区及相应法律审阅结论。
- Phase 3 在线数据、备份和日志的具体保留期限及删除完成时限。
- Phase 4 最终语音引擎及其数据处理条款。

## 11. 变更控制

以下任一变化都必须阻止直接发布，先更新本数据地图并重新审查：

- 新增 SDK、权限、远程域名或后台服务。
- 新增数据字段、服务端表、日志字段或 Sentry context。
- 改变数据用途、保留期、删除方式或共享方。
- 开放新国家/地区、国内应用商店或新的平台。
- 从单机/LAN 进入在线或语音阶段。

审查完成后，同步更新代码、隐私政策、应用内说明、Google Play Data Safety、App Store App Privacy、测试用例和发布记录。
