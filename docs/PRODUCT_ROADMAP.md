# 四子游戏产品路线图

> 状态：当前权威规划
> 决策确认日期：2026-08-01
> 说明：本路线图定义正式发布顺序和阶段边界，不代表各阶段已经完成。实际完成状态以代码、自动化测试和发布证据为准。

## 1. 产品方向

四子游戏按连续的正式阶段演进，不设置独立的“Beta 产品”。Google Play 内部测试、封闭测试和 TestFlight 等仅作为正式版本的发布验证渠道。

总体发布顺序为：

1. Phase 1：Android 正式版。
2. Phase 2：iOS 正式版，并同步完善 Android 的界面本地化。
3. Phase 3：可靠在线对战。
4. Phase 4：普通对局语音能力与中文无屏冥想模式。

Phase 1 至 Phase 4 均不接入广告和应用内购买。国内 Android 应用商店在 Google Play 版本稳定后再规划，不与 Phase 1 同步发布。

## 2. 跨阶段产品约束

### 2.1 视觉与主题

- Phase 1 对外只提供“现代东方棋艺”主题，作为默认且唯一可选主题。
- 视觉语言以纸、墨、玉、朱砂和克制木质感为基础，并与冥想模式的安静体验兼容。
- Phase 1 即建立完整主题包架构，主题包可独立定义设计令牌、字体、背景、棋盘线条、棋子、动效和音频。
- 后续主题可以整体替换体验。例如乡村主题可使用土地背景、树枝划线、小石子或树枝棋子。
- 中文展示字体和正文字体均应本地打包，并具备明确的商业使用授权；运行时不依赖网络字体。

### 2.2 屏幕与无障碍

- 手机以竖屏为主要体验。
- 平板支持横竖屏自适应，不单独设计桌面端产品形态。
- 棋子不得只依靠颜色区分。
- 支持系统字号、屏幕阅读器语义标签和“减少动态效果”。

### 2.3 数据与兼容性

- 开发期允许清理不兼容的旧存档。
- 正式 1.0 发布后，存档、统计和对局记录发生结构变化时必须提供迁移，不得静默丢失。
- Sentry 用于匿名崩溃和性能诊断，默认开启并允许用户在设置中关闭。
- 不做行为分析，不使用广告标识，不建立用户画像，不向 Sentry 发送棋局内容或敏感字段。

## 3. Phase 1：Android 正式版

### 3.1 平台与发布范围

- 最低支持 Android 8.0（API 26）。
- 发布构建以 Android 16（target API 36）为目标。
- 首发渠道为 Google Play。
- Phase 1 只声明和支持中文界面。
- 环境仅包含 development 和 production；Google Play 内部测试属于发布验证，不新增 staging 环境。

### 3.2 功能范围

- 本地双人对战。
- 三档难度的人机对战。
- 正式局域网对战。
- 单槽自动存档和首页“继续游戏”。
- 本地双人、AI 和局域网对局统计。
- 最近 20 局已完成对局的完整历史和回放。
- 规则说明与交互式教程。
- 现代东方棋艺主题、音效、背景音乐和震动设置。
- 无障碍底线能力。

在线对战、普通对局语音控制和冥想模式不属于 Phase 1，不应作为可用功能暴露或写入 Phase 1 商店描述。

### 3.3 已确认的对局行为

- 本地双人、AI 和局域网首局均随机决定先手，重赛时交替先手。
- AI 可以执黑先走，玩家也可以执白。
- 每方每回合 60 秒。
- 超时方立即判负。
- 本地双人和 AI 在应用进入后台或锁屏时暂停计时。
- 局域网逻辑时间在后台继续，由 Host 维护权威状态并同步剩余时间。
- 局域网断线提供 30 秒重连宽限；宽限期内计时继续，重连后全量同步，超时未恢复则断线方判负。
- 本地双人撤销一手；AI 模式撤销玩家和 AI 的一对走法；两者都支持重做。
- 局域网不支持撤销和重做。
- 每次已确认落子后自动保存；结局或明确放弃后清除当前存档。
- 连续 50 个单方落子（ply）未发生吃子时和棋；任意吃子后重新计数。
- 一方回合开始时无合法移动，该方立即判负。
- 一方剩余棋子数小于等于 1 时立即判负。
- 落子后同一枚移动棋子若横向和纵向同时满足吃子规则，两枚对方棋子都被吃掉。

规则的完整模式表和终局结算顺序应由独立权威规则文档定义，并由 Dart 引擎、AI、LAN 协议、后续在线服务器和测试共同遵守。

### 3.4 发布完成定义

只有同时满足以下条件，Phase 1 才能标记完成：

- Phase 1 范围内所有功能可从正式 UI 完整使用。
- 规则、计时、存档、历史、回放和 LAN 的关键自动化及真机测试通过。
- 最终包名、应用名称、签名、隐私政策、支持邮箱、Sentry 配置和商店素材齐备。
- 已生成并验证正式签名的 AAB。
- Google Play 内部测试和封闭测试完成，满足账户适用的正式发布资格要求。
- 商店描述、应用内规则、隐私声明和代码行为一致。

## 4. Phase 2：iOS 正式版与三语界面

### 4.1 平台范围

- 最低支持 iOS 13。
- iOS 完整具备 Phase 1 Android 的本地双人、三档 AI、LAN、存档、统计、最近 20 局回放、规则、教程、主题和无障碍能力。
- 完成中文、英文、日文界面本地化，并同步更新 Android。
- 在线对战、普通对局语音和冥想模式仍不属于 Phase 2。

### 4.2 发布完成定义

- iOS 工程、Bundle ID、签名、Capabilities、图标和启动资源完整。
- LAN 所需本地网络说明和 Bonjour 服务声明正确。
- iPhone 与 iPad、横竖屏、iOS 13 与当前系统版本测试通过。
- 三种语言不存在未本地化的用户可见文本，规则术语含义一致。
- TestFlight 验证、App Privacy 信息、隐私政策和 App Store 素材完成。
- Android 同版本的三语界面和规则同步发布。

## 5. Phase 3：可靠在线对战

### 5.1 环境边界

完整 staging 是 Phase 3 进入真实集成与发布门禁的前置条件；在项目方集中补齐域名、区域、平台和责任边界后建立，并与 production 隔离：

- 独立的 staging 应用配置。
- 独立的 staging 服务器和数据库。
- 独立的域名、凭证、Sentry environment 和部署流水线。
- staging 不共享 production 用户数据或密钥。

### 5.2 功能范围

- 本地随机生成的匿名设备身份。
- 不要求手机号、邮箱或真实姓名。
- 随机匹配。
- 服务端权威规则和状态同步。
- 落子确认、拒绝和恢复。
- 断线重连和全量重同步。
- 60 秒超时和确定性结算。
- 与匿名设备身份关联的在线战绩和对局记录。
- 设置页提供“删除在线数据并重置身份”。
- 不自动进行跨设备同步。

账号体系、ELO、好友房、聊天和赛季均不属于 Phase 3。

### 5.3 发布完成定义

- 客户端和服务器使用同一规则契约与协议版本。
- staging 完成契约、集成、重连、并发、超时、负载和故障恢复验证。
- TLS、数据库迁移、备份恢复、健康检查、限流、日志脱敏和 Sentry 完成。
- 数据保留和删除机制实际可执行，隐私政策与商店数据声明已更新。
- Android 与 iOS 可靠在线能力同步发布。

## 6. Phase 4：语音基础与冥想模式

### 6.1 功能范围

- 恢复普通对局语音控制和状态播报。
- 完成中文无屏冥想模式。
- 用户可以仅依靠语音引导、播报和指令完成完整对局。
- Phase 4 首期不要求多语言语音。

### 6.2 发布完成定义

- 麦克风权限仅在用户进入语音功能并理解用途后请求。
- 普通对局与冥想模式使用同一套权威游戏规则。
- 权限拒绝、识别失败、语音服务不可用、音频中断和恢复都有明确体验。
- 完整无屏流程通过真机验证。
- 语音处理方式、第三方系统服务和可能的数据传输已纳入隐私政策及商店声明。

## 7. 延后事项与阶段门禁输入

以下信息不在开发期猜测，必须在对应正式发布门禁前由项目方提供或确认：

- Phase 1：最终应用名称、永久 Android applicationId、隐私政策 URL、支持邮箱、Sentry DSN、Google Play 开发者账户状态、正式签名保管方案和商店素材。
- Phase 2：对应 iOS Bundle ID、Apple Developer Team、App Store Connect 信息和签名权限。
- Phase 3：staging/production 域名、服务器区域、部署平台、数据库和备份责任、数据保留期限、服务端 Sentry DSN。
- Phase 4：最终语音识别与播报引擎、联网/离线边界、第三方处理区域、数据保留条款及所需外部账号。
- 国内商店：在 Google Play 版本稳定后，再确认目标商店、商店合规要求、签名复用和分发计划。

任何阶段只有在发布门禁全部通过后才能称为“完成”或“可发布”。
